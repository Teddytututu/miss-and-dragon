# 报告先交研究主线精修

[English](report-review.md)

执行方准备报告、图、可核对的数字和单独的技术记录，在现有主线交流中提交成果。主线核对证据、解释和读者需求，精修后再交给发起人。结果页、带结论的数据表、学习报告和研究总结都采用这个流程。

草稿链接和审核请求放在助手交流中。主线决定精修稿的交付时间、汇报人及是否添加用户操作卡。指定汇报人在发出一次完成回复前，先看原留言已有的回复。发起人的明确指令可以另定流程。

## 精修核对内容

- 把证据最充分的答案放在开头，给出相应对照和分母。
- 分清证据来源、受控比较、观察与假说。
- 已完成的预计换成实际结果，科学术语首次出现时作解释。
- 调整叙述时保持数字、作者贡献和论断强度。
- 打开成品，核对图、公式和链接。

## 主线精修记录模板

每次审核后，把可复用的改法追加到项目本地的报告写作规范，下一份报告照着做。编辑记录与工作材料一起保存，读者版报告只放科学内容。

```markdown
## 主线精修记录

### 读者问题或报告主题

- 读者的问题：
- 修改的段落或图：
- 批准的表达或结构：
- 保持的证据与数字：
- 下一份报告采用的通用规则：
```

项目的报告说明或报告技能链接到这份本地规范。审核交流使用项目相对路径。公开源码包保留通用规则与空白模板，个人审稿记录保存在本地项目。

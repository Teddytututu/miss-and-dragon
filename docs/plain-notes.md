# Plain exchange notes

Start with the result, then say what the other assistant should do. Keep the full note or question within 600 characters. Put long identifiers, hashes and technical detail in a companion file and include its project-relative path.

Execution notes and questions are checked before writing. Dense internal terms, long hashes and oversized text return an actionable error; both exchange and question records stay as they were. Use `note` for information and review-ready results. Use `ask` when the lead must choose between concrete options. The discussion room carries results useful to the owner.

A final update says what was accomplished, why it matters and whose decision is pending, in at most two plain sentences. Routine unchanged patrols follow the existing quiet-notification preference.

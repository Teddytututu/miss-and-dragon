# 提示词写法

1. 提示词写长期规则，进度、故障和带日期的观察写进任务或交流板。
2. 按先后分步骤，一行一个动作。
3. 每条规则放在一处，其余位置写链接。
4. 使用白话，写具体动作和对象。
5. 原因用一句短话说明。
6. 稳定的要求交给程序检查，提示词指向对应程序。
7. 每周整理一次，收走过期、重复和只制造噪音的规则。
8. 负责人维护共同提示词，执行者用note提建议；用户选择模型并批准模型变更。

流程检查读取项目内的instructions.md或当前指令.md，以及attachments/wake-prompts.json中导出的提示词。后者用角色名对应文本。常驻规则超过4500字、唤醒提示超过1200字、术语扎堆或提及已归档任务时，交负责人整理。账号和宿主设置继续由用户管理。

交流写法见[白话交流](plain-notes.zh-CN.md)。用户可为负责人配置回复自检。

# 让获批实验在共享 GPU 空出来时接上

[English](optional-gpu-dispatcher.md) · [项目介绍](../README.zh-CN.md)

把可用服务器和与使用者约定的资源上限告诉Claude，她决定哪些实验可以运行。GPT再按这台服务器的实际条件搭建并接入调度器：一个资源够用时启动获批作业的小程序。

这是一份可选部署方案。看板提供任务记录、本地队列执行器和进度事件；远程调度器按服务器已有的访问与资源规则接入。

## 用起来是什么样

获批实验先排队。GPU 和磁盘空间满足条件时，调度器启动作业，状态文件列出运行中、排队、完成和失败的任务。守夜人可通过配置好的适配器读取状态，把变化交给助手。

## 先约定资源范围

Claude和GPT先核对获批访问方式、资源上限、预留设备、磁盘需求和停止条件。花费及账号操作按你当前授权处理。服务器名称、用户、设备偏好和额度写在本机部署配置中。

调度器按约定启动作业，在跑的进程和其他用户文件保持原有归属。结果、评分、设置和日志带回项目；可复算的大型中间文件按项目保留计划处理。

<details>
<summary>给开发者：调度一轮做什么</summary>

1. 用 `nvidia-smi` 读取实际显存、进程和所属用户，应用部署配置中的预留、可用条件和并发上限。调度器与观察程序共用一份容量规则，每次准入重新计算。实际计算、模型加载与有效作业预留按设备去重。当前占用超过新上限时，已获批运行的作业继续，容量恢复后接入新作业。
2. 从 `queue/` 读取获批作业，先按优先级，再按进入时间排序。规格包含 `task`、`priority`、`cmd`、`cwd`、`mem_gb`、`disk_gb`、`est_hours` 和批准记录。
3. 设备编号表示偏好，启动时重新核对实际可用条件，按规则选择合适设备；加载前检查容量。
4. 设置 `CUDA_VISIBLE_DEVICES` 后启动获批命令，把进程身份、设备和启动时间写入 `running/`。
5. 结束后归入 `done/` 或 `failed/`，保留退出状态。失败最多重试三次，记录次数和有上限的退避；确定性的配置或授权问题交回审核。计划时限按部署的保存与重排规则处理。
6. 写 `status.json` 给观察程序，附真实进度和利用率，供助手区分资源占用与实际计算。

加载时接入[资源守卫](optional-resource-guard.md)，向会话投递事件用[事件桥](optional-event-bridge.md)。凭据和机器专属命令保存在部署配置中。

</details>

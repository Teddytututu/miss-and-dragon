# 每个发现和配套文件放在一起

[English](report-tidy.md)

大肥鱼打开一张主卡看结论，点下面的小链接看数据。大小姐审核哪些材料属于同一个发现，龙娘按审核后的清单整理看板。

## 每周整理

守夜人默认按电脑本地时间，在周日 20:00 生成 `weekly_tidy` 事件。大小姐阅读这份说明，列出具体要合并、改名和移入旧材料的卡片；龙娘通过看板的文件命令修改，大小姐检查页面后确认事件。默认的 `weekly_rules` 规则复盘事件接在确认之后。

1. 每个发现保留一张主卡。CSV、Markdown、PDF、ZIP 等配套文件的 `under` 填主卡的完整 `path`。
2. 被新版取代的报告改名为“旧版（日期，已并入 X）”，连同旧配套文件归入旧材料。
3. 标题写读者能看懂的结论，任务编号留在任务记录中。
4. 入口只留“现在的结论”和“新人入门”两张，具体发现归入对应主题。

父卡归档或缺失时，配套文件照常显示为普通卡。搜索会同时匹配配套文件的名字。整理文件本体时，按项目已有的保留规则逐项处理。

<summary>给两个助手</summary>

运行 `python scripts/agent.py --as GPT file --help` 查看当前文件命令。保留已有的项目根目录、路径、分类和归档字段。新配套文件使用 `file add --under <父卡路径>`；已有卡片使用 `file edit --title <现有标题> --under <父卡路径> --new-title <读者标题>`。配套链接示例：

```json
{"title":"逐题数据","path":"reports/results.csv","under":"reports/finding.html","cat":"研究"}
```

修改沿已有加锁工具完成，在交流板记录审核清单和实际整理结果。验收后确认精确事件 ID；事件持续保留到确认，同一日历周期只生成一次。

节奏设置可改星期、时间、优先顺序和固定巡检间隔。自动模式继续按额度观测计算；订阅档位影响默认建议，固定覆盖影响实际间隔。用户提及和临近截止继续优先到 20 分钟，额度暂停沿既有规则。守夜人频率修改后重新应用本项目安装器；事件桥适配器读取 `event_cooldown` 合并叫醒。

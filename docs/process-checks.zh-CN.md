# 连续达标后收口的流程检查

一个流程问题连续十次检查达标后才算解决。检查失败，连续次数归零；观察条件暂缺，保留次数并记下原因。

```sh
python scripts/agent.py --as GPT checks run
python scripts/agent.py --as GPT checks show
```

现有 `wake` 也会运行到期检查。默认间隔三小时，从上次实际观察起计；间隔内反复醒来沿用已记次数。到期后由下一次现有唤醒实际观察，记录中的 `next_at` 表示下次检查时间。提供方的巡检安排和操作系统设置沿原配置执行。

附带示例核对：看板上每个有效执行角色都有进行中、退回或现在可开工的任务。暂停角色沿项目现有设置；所有角色暂停时记为观察条件暂缺。检查结果描述已有流程记录，由主线判断实际工作与结果含义。

另外两项核对协作记录。`patrols_on_time` 查看两个助手的巡检记录，以已记下次巡检时间加四十五分钟宽限期判断；记录缺失或时间无效时记为观察条件暂缺。`owner_answered` 查看研究、学习会话中发出两小时至二十四小时的有效用户消息：任一助手的文字回复，或与当前消息内容关联、仍然有效的 `react --enough` 决定，可以收起提醒。普通表情、示例消息和只有附件的回复继续保留文字提醒。文件收藏保持收藏用途。

在 `board/checks.py` 登记只读观察函数，返回 `ok`（`true`、`false` 或 `null`）和简短的 `detail`，再填标题、正整数目标次数、分钟间隔与函数。检查针对明确记录，科学判断交主线。

涉及时间的观察函数在登记项中设 `clocked=True`，并接受关键字参数 `now`。运行时传入本次实际观察时钟，明确指定的复现时钟也采用同一入口。观察函数读取已有流程记录，计数仍用现有项目锁保存。

模块沿现有项目锁把连续次数、最近观察、下次到期时间和最近六十次观察保存到 `data/attachments/checks.json`，存储层保留旧字节。达标后标成 `solved` 并保留记录，后续沿已解决状态展示。登记的目标次数或间隔变化时重新计数，原观察历史保持。`checks show` 直接读取记录。

## 作者完成时间

流程检查还会比较作者填写的完成时间与文件修改时间，发现超前时产生 `future_timestamp` 提醒，交 Claude 更正。这项检查独立于连续观察计数。

Markdown 范围是 `tasks/` 和 `experiment-design/` 直属目录中最近四十八小时修改的文件。带日期的 Claude 时间戳超前超过三分钟时提醒；只有时分的时间戳采用文件修改日期，超前量同时小于一小时时提醒。已识别的截止与预计用语、流转日志行及无效日期按原用途跳过。

HTML 范围是总览中登记、仍有效且位于数据目录内的 `.html` 链接。检查前 4,000 个字符中的 `Claude YYYY-MM-DD HH:MM` 格式，宽限五分钟。每个文件至多产生一条提醒，按实际完成时间更正作者时间戳。
